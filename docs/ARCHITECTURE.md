# Architecture

Written for engineers maintaining or extending the platform.

## Services (docker-compose)

```
web (nginx)  ──/api──▶  api (Fastify)  ──▶  postgres
                             │
                             ▼
                        redis ◀── worker (BullMQ) ──▶ VICIdial servers (MySQL + HTTP)
```

- **api** — REST API, auth, RBAC, recording stream proxy. Runs migrations +
  seed at boot (advisory-locked, so api and worker can race safely).
- **worker** — separate process, same image. Repeatable jobs: `tick` (enqueue a
  sync per active dialer every `SYNC_POLL_SECONDS`) and `check-recordings`.
  Concurrency 2 keeps CPU/RAM low; raise it for many dialers.
- **web** — static React build; nginx proxies `/api` (unbuffered, so recording
  Range streams pass through).

No microservice sprawl: two Node processes, one database, one queue.

## Security model

- **Sessions**: opaque 32-byte tokens in an httpOnly `qa_session` cookie; only
  the SHA-256 of the token is stored. Fixed TTL (`SESSION_TTL_HOURS`).
  Password/role/status changes revoke the user's sessions.
- **Passwords**: scrypt (Node built-in, no native deps).
- **RBAC**: roles carry permission arrays (`server/src/auth/permissions.ts`);
  every route declares `requirePermission(...)` — server-side, never UI-only.
- **Company isolation**: `companyScope(req)` resolves the company id every
  query MUST filter by; company users requesting another company get 403.
  Super admin (companyId = null, `*`) may scope to any company or all.
- **Secrets at rest**: VICIdial API/DB/recording credentials are AES-256-GCM
  encrypted with `APP_ENCRYPTION_KEY`; API responses only ever expose
  `has*Credentials` booleans, and audit rows never contain secrets.
- **Recordings**: served only through the authenticated, company-checked,
  audit-logged proxy. No public or predictable URLs.
- **Rate limiting**: global 600/min, login 10/min. Errors are sanitized (500s
  never leak internals); zod validates all input.

## Database design notes

Schema: `server/src/db/schema.ts`; migrations generated by drizzle-kit into
`server/drizzle/` and applied by the built-in migrator under a PG advisory lock.

- Uniqueness respects dialer boundaries:
  `calls(dialer, source, uniqueid)` (partial, uniqueid not null),
  `recordings(dialer, filename)`, `vici_agents(dialer, vici_user)`,
  `transfers(fronter_call_id)` — duplicate imports are structurally impossible.
- All timestamps are `timestamptz` in UTC; conversion from dialer-local time
  happens once, at import.
- Raw source rows are kept in `raw jsonb` with `first_synced_at` /
  `last_synced_at` — origin and sync time are always reconstructable.
- Mock/demo rows carry `is_mock` and are excluded from queues, stats and sync.
- Hot-path indexes: `(company_id, queue_status, xfer_time)` for queues,
  `(company_id, call_date)`, `(dialer, lead_id)`, `(phone_number)` for
  matching/search. Pagination is LIMIT/OFFSET with a 200-row page cap; exports
  are capped at 50k rows per file.
- Status transitions append to `transfer_events` (full history, including
  disposition corrections); admin actions append to `audit_logs`.
- Retention/archival: calls/recordings metadata grow linearly; the intended
  strategy is time-based archival of `calls`/`transfer_events` older than the
  business window (move to cold tables or partitioned storage) — queues only
  query recent windows, so a `pg_partman`-style monthly partition on
  `calls.call_date` is the natural next step once volume demands it.

## QA forms & scoring

- The builder edits a mutable `draft_schema` on `qa_forms`.
- **Publish** validates the definition (zod, duplicate/conditional checks),
  computes the max score, and freezes an immutable row in `qa_form_versions`.
- Evaluations reference the **version**, and completion scores server-side
  (`services/scoring.ts`): weighted yes/no / pass-fail / rating / dropdown,
  N/A handling, conditional visibility, critical auto-fail. Editing a form
  never changes completed results — by construction, not by convention.

## Frontend

React 18 + TanStack Query, Tailwind tokens (indigo `#3B4A9F` brand, switchboard
amber `#C97A10` attention; the two-series dashboard palette is CVD-validated).
Server-side pagination/filtering everywhere; tables never load full histories.
Super admins get a global company-scope selector; all other users are
hard-scoped by the server regardless of UI state.

## Testing

`server/src/**/*.test.ts` (vitest, 46 tests): transfer matching (same-dialer,
cross-dialer, ambiguity flagging, thresholds), disposition resolution
(specificity, inactive, "contains 'sale'" never counts), queue transitions
(including sale regression), scoring (weights, criticals, conditionals, N/A),
timezone round-trips (DST), crypto round-trips/tampering.

## Deliberate scope cuts (v1)

- No table partitioning yet (strategy documented above).
- Reports are CSV exports; BI-grade reporting should read a replica.
- Recording audio is streamed from the dialer, not copied — by requirement;
  add an object-store archiver if dialers purge recordings aggressively.
